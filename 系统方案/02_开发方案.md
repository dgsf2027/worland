# 沃朗科技租赁系统 · 开发方案

> 版本：v1.0（待评审）　|　日期：2026-08-07
> 定位：智慧园区平台下的「**租赁板块**」　|　技术栈：Spring Boot 2.7 + Vue3 + MySQL8 + SSO（与园区小卖账房同栈同平台）
> 上游依据：《调研报告》（42 产品）+ 沃朗《设立方案书 V14.0》+ 园区小卖账房《设计七律/开发铁律》。

## 一、定位与架构

### 1.1 它是什么
租赁系统**不是一套独立系统**，而是**智慧园区平台里的一个功能板块**，与「园区小卖账房」是同一平台下的兄弟板块：

```
                    智慧园区平台（同一账号 · SSO · 统一权限）
   ┌──────────────┬──────────────┬──────────────┬─────────────┐
   │  园区小卖账房  │  🆕 租赁板块   │  （其他板块）  │  平台公共层   │
   │  (已开发)     │  (本方案)     │              │ 账号/组织/权限 │
   └──────────────┴──────────────┴──────────────┴─────────────┘
        用户登录 → 开通「租赁板块」权限 → 进入即用
```

- **同一账号登录**：复用平台 SSO，不自建登录。
- **权限开通即用**：给用户账号开「租赁板块」权限后，登录就能看到并操作。
- **先独立、后嵌入**：先作为可独立运行的板块跑起来（数据/接口自洽），再挂进智慧园区主框架。因此**架构上按"平台内模块"设计**：独立库表前缀（建议 `yc_rent_`）、独立菜单、复用平台账号与权限模型。

### 1.2 复用什么、新建什么
| 复用平台/小卖账房 | 租赁板块新建 |
|---|---|
| SSO 登录、组织/员工/角色权限 | 供应商、客户、设备资产、租赁合同、租金计划 |
| 业财一体单据链内核（单据→凭证→核销） | 租金收入单、采购入库单、转让单、维修单 |
| 导入中心、AI 透明四件套、审批流组件 | 报价测算器、现金流/分配驾驶舱、风控引擎 |
| 报表 BI 框架、移动端响应式框架 | 资产状态机（租→转让）、逾期三步走 |

### 1.3 技术选型理由（对齐调研第三章）
- **不采用 Odoo/ERPNext 做底座**：与"嵌入智慧园区、同栈、同账号"冲突，本土化/定制成本高。
- **自建租赁板块 + 照抄开源数据模型**：折旧明细行、双套账、租金计划表、资产状态机这些高风险地基，**照搬 Odoo `account.asset.line` / ERPNext 多 Finance Book 的成熟表结构**，不从零发明。

## 二、设计 DNA（直接继承园区小卖账房「设计七律」）

租赁板块与小卖账房同平台、同团队，**沿用同一套设计七律**，避免两套体验割裂：

1. **一个案例，全局排查**：用户点一个问题（如某合同租金算错），同尺扫全系统同类问题。
2. **不只给结果，领着人干活**：干活页顶部两件套——⚡任务来源 + 编号流程条（当前步高亮）。
3. **任何名词都能点进去**：设备、合同、供应商、客户、出资人五大实体都有"体检报告式"详情页，列表名词可下钻。
4. **每分钱有来处去处**：钱只被单据改；业财一体单据链（确认签字→自动生成财务单→凭证→自动核销）；"钱该动没动"亮灯；红冲/退租/调整/锁账逆向路径完整。
5. **管理要闭环（PDCA）**：每环节 C 指标红绿灯，改进落 action_item 表到期回查。
6. **效率三问**：能不能不选（扫码/自动匹配）？能不能不打字（预填/AI 识别合同）？能不能不跳页（卡上原地操作）？
7. **AI 只做解释/抽取/起草，规则引擎出数字**：LLM 永不算租金/回报/账，只做合同抽取、风险解读、月报起草；结论旁挂 🔬 过程入口，模型可切换。

> 加一条**租赁专属铁律**：**上下游价格账期严格保密 + 项目独立核算**——数据行级隔离，权限控制谁能看某项目/某合同的成本价。（这是小卖账房没有、租赁必须有的。）

## 三、十维分析：系统怎么承接「业·财·人·事·物 + 时·钱·风·关系·保密」

你给的五维（业财人事物）+ 我补的五维（时/钱/风/关系/保密），逐维落到系统：

### 业（业务主线）
选品 → 开发供应商 → 报价测算 → 签约 → 采购投放 → 收租 → 到期转让。对应模块：**供应商管理、报价测算器、合同管理、投放/交付、收租、转让**。

### 财（财务）
业财一体：每笔业务单据自动生成凭证；两套账（税务口径"分期收款销售" / 经营口径"三层回报"）；管理费阶梯、每月 5 号分配、留存≥20 万。对应模块：**凭证中心、双账台账、分配管理、税务合规看板**。

### 人（人事）
起步从简：花名册 + 角色权限 + 任务派工 + 提成（供应链谈成一单的贡献）。对应模块：**员工/角色、任务中心（绑角色绑人留痕）**。HR 深度后置。

### 事（运营事务/流程）
任务与审批：投放审批（300 万内自主）、逾期处理、维修派工、盘点。对应模块：**任务中心、审批流、投放审批、维保工单**。

### 物（资产/设备）
设备逐件台账（采购→投放→在租→维保→转让→残值）+ 扫码盘点 + BOM/泵表成本。对应模块：**设备资产台账、供应商库、盘点、维保**。

### 时（生命周期）——补
设备生命周期 + 合同生命周期两条主线可视化；每台设备/每份合同都有"命"的时间轴。对应：**设备详情页时间轴、合同详情页租金计划表 + 阶段状态机**。

### 钱（现金流/杠杆）——补
**现金流/分配驾驶舱**（调研发现的差异化空白）：应收 × 账期到期分层（1年内/外）× 每月分配计划 × 留存下限 × 三层杠杆监控。对应：**现金流驾驶舱**。

### 风（风控红线）——补
客户准入授信、逾期三步走（延期→罚息→锁机/收回）、设备空置预警、负债率红线、500 万税务红线亮灯。对应：**风控引擎 + 红线看板**。

### 关系（多方视角）——补
同一套数据不同人看不同页：供应商关系、客户 CRM。**合伙人（GP/LP）不设员工可见的实时门户**——出资/回报/分配这类敏感信息改由**月度报表（分配表 + 经营分析报告）**按角色、周期性提供（对齐设立方案书"每月向合伙人提交财务报表"）。对应：**CRM、月度报表**。
> ⚠️ 隐私铁律（用户拍板 2026-08-07）：运营系统由员工日常操作，**合伙人出资额/占比/个人收益绝不对普通员工可见**——不做实时出资人门户；月度报表的「分配表」按角色可见，普通员工导出的报表包不含此表。

### 保密（隔离）——补
项目独立核算、上下游价格保密、行级数据隔离、成本价字段级权限。对应：**权限与数据隔离层**（贯穿所有模块）。

## 五、核心数据模型（关键表 · 照抄开源成熟结构）

> 库表前缀 `yc_rent_`。以下为主干，评审通过后进 DESIGN_DOC 细化字段。

| 表 | 作用 | 抄谁 |
|---|---|---|
| `supplier` 供应商 | 四维评估、集采价、账期、BOM | GLPI Infocom |
| `customer` 客户 | 风控、授信、类型（云仓/园区/外部）、目标 IRR | 通用 CRM |
| `asset` 设备（逐件） | 序列号、品类、市场价/集采价、**状态机**、当前在谁手上 | Snipe-IT `assigned_to` 多态 + ERPNext Asset |
| `asset_status_log` 资产事件流 | 采购→投放→在租→维修→转让全部留痕 | ERPNext 资产事件外键 |
| `contract` 租赁合同 | 客户、设备、租期、目标 IRR、期末转让价、状态阶段 | NETSOL/Alfa 期末阶段 |
| **`rent_schedule` 租金计划表（逐期明细行）** | 一份合同 N 期，每期应收额/到期日/状态/挂凭证 | **Odoo `account.asset.line`（必抄）** |
| `rent_bill` 收租单 | 每期到点生成、收款、核销、逾期 | 融资租赁通用 |
| `overdue_case` 逾期案 | 三步走：延期→罚息→锁机/收回 | 国内融资租赁 |
| `transfer_order` 转让单 | 租满转让、残值、账务切换 | Rentle 处置 |
| `purchase_in` 采购入库 | 集采、首付/账期、应付 | InvenTree 采购链 |
| `voucher` 凭证 | 业财一体，单据→凭证 | 好业财/园区小卖账房 |
| `ledger_book` 账套 | **双账：税务口径 / 经营口径** | **ERPNext 多 Finance Book（必抄）** |
| `distribution` 分配 | 每月 5 号、50%现金/50%滚存、留存≥20万；进月度报表「分配表」按角色可见 | 沃朗独有（自建） |
| `investor` 出资人 | GP/LP、出资额、比例（仅供分配计算，**不设员工可见门户**） | 沃朗独有 |
| `monthly_report` 月度报表 | 报表包六件套 + 经营分析报告七节 + 财务日历 | **学园区小卖账房 M4 月报包** |
| `action_item` 改进项 | PDCA 闭环 | 园区小卖账房 |

**两条最值钱的照抄**：
1. **租金计划表** = Odoo 资产折旧明细行的结构（主表 contract + 逐期 rent_schedule 明细行 + 每行到点生成 rent_bill→voucher）。融资租赁的心脏。
2. **双套账** = ERPNext 多 Finance Book（同一笔业务，税务口径按"分期收款销售"、经营口径按"三层回报"，两套并行不打架）。

## 六、业财一体单据链（每分钱有来处去处）

```
签约(合同) ──► 生成租金计划表(N期)
采购(集采) ──► 采购入库单 ──► 应付凭证(首付/账期)
每月到期  ──► 收租单(自动生成) ──签收──► 收入凭证 ──► 自动核销应收
逾期      ──► 逾期案:延期→罚息单→锁机/收回单
租满      ──► 转让单 ──► 残值收入凭证 + 资产出账
月底      ──► 管理费计提 ──► 每月5号分配单(现金/滚存) ──► 出资人门户
```
逆向路径（红冲/退租/调整/锁账补导）全部规则化——ERP 死穴全在逆向，照小卖账房铁律做完整。

## 七、里程碑（全量规划 · 分期交付）

| 里程碑 | 交付内容 | 为什么这个顺序 |
|---|---|---|
| **冲刺 0**（先于业务码） | 用《设立方案书》真实数字跑通"报价测算器"，与设立方案书定价表/速算系数**对平**；核实税务口径；确认与智慧园区平台的账号/权限打通方式 | 数字对不平就返工，同小卖账房打法 |
| **M1 业务地基（业+物）** | 供应商库、客户档案、设备逐件台账+状态机、报价测算器、合同+租金计划表 | 先把"业和物"的主线跑通 |
| **M2 收租闭环（业+财）** | 收租单自动生成、业财一体凭证、逾期三步走、锁机 | 钱开始流动 |
| **M3 财务与分配（财+钱+关系）** | 双套账、管理费阶梯、每月5号分配、现金流驾驶舱、出资人门户、税务红线 | 有限合伙的核心 |
| **M4 转让与资产闭环（物+时）** | 租满转让单+账务切换、残值、维保工单、扫码盘点 | 资产走完一生 |
| **M5 事+人+BI+AI** | 任务/审批/派工、花名册/权限/提成、BI 驾驶舱、PDCA、AI 月报/合同抽取 | 管理闭环收口 |

上线节奏：功能全开发、开关分批启用（业务→收租→财务→BI 逐月开），与人工台账并行对账 1 个月。

## 八、风控与红线内置（系统级强约束）

- **投放审批看层级① 本金回报率**：报价测算器不达目标 IRR 不允许签约。
- **逾期三步走**内外一视同仁，系统自动跑，物权在我方可锁机。
- **先签约后采购**：无合同不允许生成采购单（防设备空置）。
- **税务红线亮灯**：合同禁写"融资租赁"（字段校验）；营收逼近 500 万预警（防被迫转一般纳税人）。
- **保密隔离**：成本价/账期字段级权限，项目行级隔离，谁能看在权限里配。
- **单一真相源**：派生数据（在租率、应收、现金流）只由事件流/单据算出，禁直写。

## 十、开放问题（评审时定）

1. 报价测算器的**默认参数**（年化资金成本 r、各品类残值率）由财务给还是先用《设立方案书》基准值？
2. **月度报表**的分配表/经营分析报告放哪个里程碑（建议 M3 随财务分配一起）？合伙人拿到的报表口径与颗粒度由财务定。
3. 与智慧园区平台的**账号/权限**对接：是等平台就绪，还是先用占位头（X-User）独立跑（同小卖账房上线前做法）？
4. **人事维度**深到哪（仅花名册+提成 vs 含考勤/薪酬）？
5. AI 能力一期做哪些（合同抽取/风险解读/月报起草）？
